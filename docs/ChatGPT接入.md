## 飞书应用与 ChatGPT

1. 在测试组织使用自建应用，按 `config/feishu-mcp-permissions.json` 核对权限。应用权限启用后，员工仍须授权自己的身份权限。
2. 将本地 `127.0.0.1:3010` 接到 HTTPS 入口，设置同一 `MCP_PUBLIC_URL`，重启服务。
3. 飞书应用“安全设置”的重定向 URL 填 `MCP_PUBLIC_URL/feishu/callback`。
4. 在已登录 ChatGPT 的“插件 → 添加自定义 MCP 服务器”填写 `MCP_PUBLIC_URL/mcp`，选择 OAuth。高级设置选择动态客户端注册（DCR），默认范围勾选 `mcp`，基础范围留空，关闭 OIDC 邮箱识别。保留自动发现的端点；不要把飞书 App Secret 填进 ChatGPT。
5. 按页面跳转，由员工登录飞书、核对权限并授权，再确认连接公司飞书助手。
6. 先调用身份与资源列表，再在虚构数据中逐项验证。若 ChatGPT 账户没有自定义 MCP 入口，需先核对该账户或工作区的可用功能。

首版仅允许 ChatGPT 官方回调地址，尚未适配 WorkBuddy 等其他客户端。
测试使用临时 Cloudflare 隧道；服务进程或隧道退出就会断开。重建隧道可能改变地址，届时需要更新本地地址、飞书回调以及 ChatGPT 连接。正式使用应改为固定域名与长期运行服务。

## 写入、恢复与限制

- 文档支持创建、追加以及替换指定普通文字段落；修改先检查版本，冲突后重新读取，不覆盖整篇文档。
- 附件保持 PDF/DOCX/XLSX/TXT 原格式，最大 20 MiB，上传后移入知识库；下载链接必须为可验证的公网 HTTPS 地址。
- 写操作必须带唯一 `operation_key`，同一操作重试沿用编号。不同内容复用编号会被拒绝。
- `success` 表示收到对应成功结果；`pending`/`uncertain` 不能当作完成。通过回执检查已记录的阶段，不得换编号自动重发。
- 文件移入的异步任务若未返回节点，保留文件标识和任务标识；调用 `get_operation_status` 时查询已保存的任务并核实当前访问权限、目标空间和原上传文件。完成后更新为 success 并返回知识库链接；尚未完成仍保持未确认状态。此过程只读飞书，不重新上传或重新发起移入。
- 群历史与文档分页未读完，不能声称已获取全部；空消息结果不能推断当天无成交。
- 飞书授权和 MCP 状态存放于独立 `data/bridge.db`，载荷加密，密钥为 `data/bridge.key`。数据库与密钥须一起备份，限制本机读取权限；不要上传仓库。
- `.env.local`、`data/`、`tmp/` 已由 Git 忽略。正式部署还需确定运维与备份方式；当前未完成生产验收。
