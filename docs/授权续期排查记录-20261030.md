# 授权续期排查记录

日期：2026-10-30。范围：本地代码与隔离模拟测试；尚未核实线上部署版本或服务器日志。

## 已复现

- 同一员工的两个独立助手连接可分别续期，不能把故障直接归因于助手数量。
- 当前完整 OAuth 登录流程发出的刷新凭证绑定登录会话。会话配置为 3600 秒；模拟经过 3601 秒后，两种请求 scope（`openid offline_access mcp`、`mcp`）均返回 `invalid_grant`。
- 飞书续期请求出现模拟网络异常后，现有代码删除员工凭证；之后 MCP 续期也返回 `invalid_grant`。
- 重复使用已轮换的 MCP 刷新凭证会撤销对应 grant。这是安全保护行为，不应简单关闭。

## 待处理

1. 核对线上实际版本和脱敏错误记录，确认用户故障对应的环节。
2. 调整长期授权与登录会话绑定策略，保持撤销授权和权限检查有效。
3. 区分授权明确失效、网络异常和刷新结果不确定，避免把所有失败都当成同一种情况。
4. 验证跨时段续期、多连接、服务重启和授权撤销；结果不确定时不得盲目重用轮换凭证。

本次排查未修改线上服务，也未宣称问题已修复。SSH 密钥登录被服务器拒绝，线上核查需可用的服务器入口。
