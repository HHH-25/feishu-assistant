# 接口说明（D4 草稿）

基址：`http://localhost:3000`（可用 `PORT` 覆盖）  
统一错误体：

```json
{
  "ok": false,
  "error": {
    "code": "FORBIDDEN_SPACE | VALIDATION | NOT_FOUND | UPSTREAM | CONFLICT",
    "message": "人类可读说明",
    "request_id": "..."
  }
}
```

请求可带 `x-request-id`。mock 模式可用 `x-operator` 演示身份；real 模式必须使用 `Authorization: Bearer <API_ACTORS_JSON 中的 key>`，请求体中的 operator 不作为身份依据。

启用飞书管理员网页时，`GET /admin` 提供页面；`POST /admin/auth` 使用飞书 H5 登录码建立服务端签名会话。页面调用 `/admin/api/me`、`GET/POST /admin/api/archives`、`POST /admin/api/daily-summary` 和 `GET /admin/api/daily-summary/:businessDate`。这些路由只接受已列入 `ADMIN_WEB_ACTORS_JSON` 的飞书身份，写操作要求同源 `Origin` 和会话 CSRF 头；不接受浏览器传入 API Bearer Key。默认关闭，真实工作台联调未完成。

## POST `/api/v1/archives`

multipart 归档文件。

| 字段 | 必填 | 说明 |
| --- | :---: | --- |
| `file` | ✓ | PDF / DOCX / XLSX / TXT，≤ 20MB |
| `department` | ✓ | 部门 |
| `confidentiality` | ✓ | `public` / `dept` / `mgmt` / `finance` |
| `space_id` | ✓ | 目标空间；财务空间需 elevated 操作者 |
| `operator` | ✓ | 操作者；也可用头 `x-operator` |
| `source` | | 默认 `api` |
| `file_type` | | 可省略，从扩展名推断 |
| `owner` | | 责任人，默认=operator |

**成功 / 去重 200**：含 `archive_id`、`file_id`、`feishu_url`、`content_hash`、`version`、`status`、`deduplicated`、台账关键字段。  
**无权限 403**（`FORBIDDEN_SPACE`，已记审计）  
**校验失败 400**

上传或台账写入失败时返回 503，并在错误消息中附 `archive_id`。归档记录保留 `pending` 或 `failed` 状态；用原文件重试可在已保存文件标识时复用该文件。

同空间同 SHA-256 → `deduplicated: true`，不新建飞书文件。  
同名同部门同空间、哈希不同 → `version` 递增，`previous_file_id` 指向旧版。

## GET `/api/v1/archives/:archiveId`

查询台账快照。

**200** `{ "ok": true, "archive": { ... }, "upload": { "state": "committed | uploaded | uncertain | uploading" } }`
**404** 不存在

## GET `/api/v1/archives`

按当前可信身份列出可访问的归档台账，可选 `space_id`、`file_name`（包含匹配）、`department`、`status`、`page`（默认 1）和 `page_size`（默认 50，最大 100）。按上传时间倒序返回 `archives`、当前身份可见记录的 `total`、`page` 和 `page_size`。不返回未授权空间或财务密级记录，也不把它们计入 `total`；明确指定无权访问的 `space_id` 返回 403 并记审计。真实模式仍需 Bearer 凭证。

此接口可供后续管理员页面查询文件位置、提交人、版本和处理状态；当前尚未提供飞书内页面。

## POST `/api/v1/daily-summary/run`

手动（或模拟 cron）触发某日汇总；与 20:00 定时共用业务逻辑。

```json
{
  "business_date": "2026-10-14",
  "operator": "admin",
  "trigger": "manual"
}
```

**200**：`run_id`、`missing`、`summary_id`、`revision`、`message_sent`、`idempotent_skip_send`、`content_preview`。  
同日已推送则更新修订版且 **不再发送新消息**（`idempotent_skip_send: true`）。

---

## GET `/api/v1/daily-summary/schedule`

查看进程内定时状态（是否启用、时区、上次触发业务日）。真实系统 cron 可后置。

## GET `/api/v1/daily-summary/:businessDate/status`

管理者查询该日任务记录和发送回执。`send.state` 为 `sending` 或 `uncertain` 时必须先核对管理群，不自动重发。

## POST `/api/v1/recovery/message`（real，管理者）

核对群消息后，传 `{"business_date":"2026-10-14","delivered_message_id":"om_..."}` 表示已送达；或传 `{"business_date":"2026-10-14","confirmed_not_delivered":true}` 表示确定未送达，允许下一次运行发送。仅处理待核对状态；操作写审计。

## POST `/api/v1/recovery/upload`（real，管理者且有目标空间权限）

核对目标文件夹后，传 `{"archive_key":"hash:<sha256>|space:<space_id>","file_id":"...","feishu_url":"..."}` 表示已上传，供原文件重试复用；或传 `{"archive_key":"...","confirmed_no_upload":true}` 表示确定未上传，允许重传。仅处理待核对状态；操作写审计。

## MCP 工具（stdio）

`npm run mcp` 启动：`archive_file` / `get_archive_status` / `trigger_daily_summary`。`archive_file` 传 `content_base64`，其余字段与 REST 相同；操作者由 `MCP_API_KEY` 映射，工具参数不得自报身份。
