## 已处理的问题

1. real 入口此前直接信任请求中的 `operator`，现改为环境配置的 Bearer 凭证映射身份，并检查空间允许清单、财务标志与汇总权限。归档查询也执行空间检查。Mock 仍使用演示身份，仅监听本机地址。
2. 定时任务先前在失败前记下当天已触发，阻止当日重试；现只在成功后记录。
3. 摘要此前在消息发送后才保存；现先保存摘要和来源，再发送，失败可查并可重试。
4. 同一进程同一业务日的并发汇总现返回 409，避免同时发送两条消息。
5. 上游异常正文不再直接返回 REST 客户端或写入运行记录，避免意外泄露凭证。
6. 文件归档先写待处理台账，上传后保存文件标识，再写完成态；完成态写入失败时，原文件重试可复用已上传的文件。单进程内同哈希并发请求会返回 409。

## 未完成与风险

- 飞书测试租户、应用权限、目标空间/表格、机器人、模型密钥及测试账号尚未备齐。真实 `FeishuClient`、`ModelClient` 仍为占位；T1–T10 无法判定真实验收通过。
- MCP 仍只有工具定义，没有可调用的 Server。
- Mock 内存数据重启即失；真实环境还需持久化状态和跨进程原子幂等。
- 消息服务若已接受发送、但响应或后续写入失败，仍存在不确定送达窗口。真实接入时需按平台能力引入消息幂等键或发送结果核对，不能仅凭当前单进程测试声称“绝不重复”。
- 上传成功后若保存文件标识及失败态也同时失败，仍可能留下孤儿文件；真实联调前需补偿或对账。
- 日报来源目前保存记录 ID，真实记录链接及权限过滤需结合多维表配置完成。
