# 第 1 日设计文档

> 不依赖飞书真实凭证。规格以任务书 V1.0（2026-10-13）为准。

---

## 1. 需求复述

### 1.1 目标

在测试环境跑通两个端到端闭环，证明权限、日志、失败重试与重复执行处理正确。飞书是正式数据源与权限载体；模型只处理授权数据，不保存飞书密钥，不能绕过飞书权限。

### 1.2 双闭环

**文件入口**

```
本地文件 / GPT 产物 → Connect/MCP → 集成服务 → 飞书云盘/知识空间 → 文件台账
```

1. 上传并提供部门、文件类型、保密等级、目标空间。  
2. 校验身份、空间权限、格式与大小。  
3. 计算哈希，识别重复与版本变更。  
4. 调用飞书上传（Office 可导入在线文档）。  
5. 台账写入飞书文件标识、链接、来源、责任人、状态。  
6. **飞书写入 + 台账均成功**才算完成；返回可核验链接与结果。

**日报出口**

```
员工日报多维表 → 每天 20:00 Asia/Shanghai → 模型摘要 → 管理汇总表 → 机器人推送
```

1. 每人每天最多一条有效日报。  
2. 按时区查询应交与已交名单。  
3. 识别正常/迟交/重复/未交。  
4. 权限过滤后按固定模板调用模型。  
5. 保存摘要、来源与执行日志，机器人推送管理者。  
6. 同日重复执行不重复发送；更新原结果或明确修订版。

### 1.3 R1–R10（必做）

| 编号 | 能力 | 本期落地要点 |
| --- | --- | --- |
| R1 | 飞书应用鉴权 | 服务端取 token 并缓存；密钥仅环境变量 |
| R2 | 文件归档 | PDF/DOCX/XLSX/TXT → 指定目录 |
| R3 | 归档台账 | 标识、链接、哈希、部门、密级、来源、责任人、版本、状态 |
| R4 | 重复与版本 | 同哈希不重复归档；内容变则新版本可追踪 |
| R5 | 日报数据结构 | 员工/日期/完成/关键数据/问题/明日计划等 |
| R6 | 定时汇总 | 20:00 查日报、缺交识别、模型总结 |
| R7 | 回写与推送 | 管理摘要 + 机器人 |
| R8 | 幂等与重试 | 不重复发消息；短暂失败可重试不丢数据 |
| R9 | 权限与审计 | 普通用户不可读写财务测试空间；操作可追溯 |
| R10 | 运行交付说明 | 可复现部署/配置/测试/演示 |

### 1.4 明确不做

- 不迁移企业全部历史文件  
- 不建设全公司 RAG/向量问答  
- 不接真实 CRM/ERP/生产库  
- 不处理真实财务/客户隐私/员工敏感数据  
- 不要求私有化大模型、训练、复杂音视频、移动端  
- 不以 UI 精美代替闭环完成度  

### 1.5 评分红线（实现时始终遵守）

- 密钥/令牌不入库、不进日志、不进前端、不进截图  
- 普通用户不可触达财务测试空间  
- 不用真实敏感数据测模型  
- 不伪造接口调用与演示数据

## 2. 架构说明

### 2.1 分层

```
┌─────────────────────────────────────────┐
│  Connect / MCP 适配层（薄）              │
│  archive_file / get_archive_status /    │
│  trigger_daily_summary                  │
└─────────────────┬───────────────────────┘
                  │ 调用
┌─────────────────▼───────────────────────┐
│  集成服务（业务规则所在）                 │
│  ArchiveService / DailySummaryService   │
│  鉴权 · 幂等 · 审计 · 重试 · 调度        │
└───────┬─────────────────────┬───────────┘
        │                     │
┌───────▼───────┐     ┌───────▼───────┐
│ FeishuClient  │     │ ModelClient   │
│ mock | real   │     │ mock | real   │
└───────────────┘     └───────────────┘
        │                     │
   飞书开放 API            模型 API
```

**原则**：业务逻辑在集成服务；MCP 只做参数映射与权限门禁。不接 ChatGPT 时，用 REST 即可验核心能力。

### 2.2 客户端可切换

| 环境变量 | 值 | 行为 |
| --- | --- | --- |
| `CLIENT_MODE` | `mock`（默认） | 内存台账/日报/消息，无外网 |
| `CLIENT_MODE` | `real` | 走真实 Feishu/Model（凭证未齐前为 stub/TODO） |

`FeishuClient` / `ModelClient` 为接口；工厂按配置注入实现。凭证未齐阶段 **禁止把主路径绑死在真实 API**。

### 2.3 运行时组件

| 组件 | 职责 |
| --- | --- |
| HTTP 服务 | REST：归档、查状态、手动汇总、健康检查 |
| MCP 适配（草案） | 暴露同能力工具，内部调集成服务 |
| 调度器 | cron `0 20 * * *` Asia/Shanghai；与手动触发共用业务逻辑 |
| 配置 | 全部来自环境变量 |
| 日志 | 结构化 JSON：requestId、操作者、资源、起止、状态、错误 |

### 2.4 数据流（摘要）

- **归档**：校验 → 哈希 → 查台账去重/版本 → 上传 → 写台账 → 审计 → 返回  
- **日报**：拉应交/已交 → 缺交 → 调模型 → 写摘要表 → 幂等推送 → 写执行记录

## 3. 数据模型

### 3.1 文件台账（必填 + 建议）

| 字段 | 必填 | 说明 |
| --- | :---: | --- |
| file_name | ✓ | 文件名称 |
| file_id | ✓ | 飞书文件标识 |
| feishu_url | ✓ | 可核验链接 |
| content_hash | ✓ | SHA-256 |
| department | ✓ | 所属部门 |
| file_type | ✓ | pdf/docx/xlsx/txt… |
| confidentiality | ✓ | 公司公共/部门内部/管理层/财务机密 |
| uploader | ✓ | 上传人 |
| source | ✓ | 来源（本地/GPT/…） |
| uploaded_at | ✓ | 上传时间 |
| status | ✓ | pending/success/failed/duplicate |
| owner | | 责任人 |
| version | | 版本号 |
| previous_file_id | | 原文件标识（版本链） |
| error_message | | 错误信息 |
| model_status | | 模型处理状态 |
| updated_at | | 最后更新时间 |
| space_id | ✓（实现） | 目标空间，权限判断用 |
| archive_key | ✓（实现） | 幂等业务键，见下 |

### 3.2 员工日报

| 类别 | 字段 |
| --- | --- |
| 身份 | date, employee, department, submitted_at |
| 工作 | done_today, metrics, unfinished, problems, tomorrow_plan |
| 管理 | need_help, need_boss_decision, attachments, submit_status |

每人每天最多一条 **有效** 记录；重复提交标记为 duplicate，不进入摘要主集。

### 3.3 管理摘要 / 任务执行记录

| 实体 | 关键字段 |
| --- | --- |
| 管理摘要 | summary_id, business_date, content, source_report_ids, missing_employees, revision, created_at |
| 任务执行 | run_id, job_type, business_date, trigger(manual/cron), status, message_id, error, started_at, finished_at |

### 3.4 幂等业务键

| 场景 | 业务键 | 冲突策略 |
| --- | --- | --- |
| 文件归档（内容未变） | `hash:{content_hash}` + 可选 `space_id` | 返回已有归档，不新建飞书文件 |
| 文件版本 | `name+dept+space` 链 + 新 hash | 新版本，`previous_file_id` 指向旧版 |
| 日报有效记录 | `{employee}:{YYYY-MM-DD}` | 首条有效，其后 duplicate |
| 日报汇总推送 | `daily_summary:{YYYY-MM-DD}` | 已推送则更新摘要或 `revision+1`，不二次发「新消息」 |
| 台账写入 | 与归档结果同一 `archive_id` | 写失败可重试，成功态幂等 |

## 4. REST + MCP 接口草案

### 4.1 REST

基址：`http://localhost:3000`（可配置 `PORT`）

#### `GET /health`

```json
{ "ok": true, "mode": "mock", "time": "ISO8601" }
```

#### `POST /api/v1/archives`

归档文件（multipart 或 JSON+base64；MVP 支持 multipart）。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| file | file | 必填 |
| department | string | 必填 |
| file_type | string | 可选，缺省从扩展名推断 |
| confidentiality | string | 必填：public/dept/mgmt/finance |
| space_id | string | 必填 |
| source | string | 默认 `api` |
| operator | string | 操作者（mock 下用请求头或字段） |

**成功 200**

```json
{
  "ok": true,
  "archive_id": "...",
  "file_id": "...",
  "feishu_url": "...",
  "content_hash": "...",
  "version": 1,
  "status": "success",
  "deduplicated": false
}
```

**重复 200**（`deduplicated: true`, `status: "duplicate"`）  
**无权限 403**（审计已记）  
**校验失败 400**

#### `GET /api/v1/archives/:archiveId`

查询归档状态与台账快照。

#### `POST /api/v1/daily-summary/run`

手动触发某日汇总（与 20:00 共用逻辑）。

```json
{
  "business_date": "2026-10-14",
  "operator": "admin"
}
```

**响应**

```json
{
  "ok": true,
  "run_id": "...",
  "business_date": "2026-10-14",
  "missing": ["员工C"],
  "summary_id": "...",
  "revision": 1,
  "message_sent": true,
  "idempotent_skip_send": false
}
```

### 4.2 错误体约定

```json
{
  "ok": false,
  "error": {
    "code": "FORBIDDEN_SPACE | VALIDATION | NOT_FOUND | UPSTREAM | CONFLICT",
    "message": "人类可读说明",
    "request_id": "..."
  }
}
```

### 4.3 MCP 工具清单（草案）

| 工具名 | 对应服务 | 输入要点 | 输出要点 |
| --- | --- | --- | --- |
| `archive_file` | ArchiveService.archive | 文件引用或路径元数据 + 部门/密级/空间 | archive_id, url, hash, status |
| `get_archive_status` | ArchiveService.getStatus | archive_id | 台账字段 + status |
| `trigger_daily_summary` | DailySummaryService.run | business_date?, operator | run_id, missing, summary, push 结果 |

MCP 层不做哈希/权限规则，全部委托集成服务。本期骨架可先实现 REST；MCP 以类型/清单预留，凭证与 Connect 就绪后再挂载。

## 5. 风险清单

| ID | 风险 | 影响 | 缓解 |
| --- | --- | --- | --- |
| K1 | 飞书租户/权限延迟 | 正式计时无法开始 | 检查表催办 + 2h 留证；先 mock |
| K2 | 财务空间误配权限 | 触发安全红线 | 业务层二次校验 space + 操作者；单测覆盖 T2 |
| K3 | 密钥泄露 | 红线不通过 | .env 不入库；日志脱敏；.gitignore |
| K4 | 同日重复推送 | 稳定性扣分 | 幂等键 `daily_summary:date` |
| K5 | 模型幻觉补写事实 | 摘要不可信 | 提示词约束 + 缺信息标注；失败保留原数据 |
| K6 | 飞书/模型短暂失败 | 丢数据或半成功 | 重试队列；状态机 pending→success/failed |
| K7 | 哈希碰撞或大文件 | 误判重复/超时 | SHA-256；大小上限；流式哈希 |
| K8 | 时区错误 | 20 点跑错日 | 固定 Asia/Shanghai；单测业务日边界 |
| K9 | Mock 与 Real 行为漂移 | 联调返工 | 接口契约统一；切换仅工厂 |
| K10 | 过度设计 MCP | 延期 | 先 REST 验闭环，MCP 薄适配 |

### 当前已知限制

- 真实 `FeishuClient` / `ModelClient` 仅为 stub，默认 mock。  
- MCP Server 进程未在本期挂载，仅有接口草案与后续挂点。  
- 定时器在 mock 下可用手动 API 等价验证（T7 逻辑共用）。
