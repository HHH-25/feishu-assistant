# 部署与联调说明

当前默认 `CLIENT_MODE=mock`、`MODEL_MODE=mock`。可先用 `CLIENT_MODE=real`、`MODEL_MODE=mock` 对接飞书测试租户，再接入真实模型。真实接口仍须在测试租户逐项核验。

## 启动

- Node.js ≥ 22.16（使用内置 `node:sqlite`）
- `npm ci`、`npm run typecheck`、`npm test`、`npm start`
- MCP stdio：`npm run mcp`，由 MCP 宿主以进程方式启动；`MCP_API_KEY` 使用 `API_ACTORS_JSON` 中的一个密钥。日志写入 stderr，不污染协议 stdout。
- HTTP 默认只监听 `127.0.0.1:3000`。生产部署需由受控网关提供 TLS、访问限制与密钥注入。

## 真实模式环境变量

复制 `.env.example` 仅作字段参考，正式密钥通过运行环境或本地忽略的 `.env` 注入。`CLIENT_MODE=real` 会在启动时检查飞书必需项；只有 `MODEL_MODE=real` 才检查 `MODEL_API_KEY`。

| 类别 | 变量 | 用途 |
| --- | --- | --- |
| 入口 | `API_ACTORS_JSON` | Bearer 密钥与可信操作者、空间清单、汇总权限、财务权限映射 |
| 飞书 | `FEISHU_APP_ID`、`FEISHU_APP_SECRET` | 获取并缓存 `tenant_access_token` |
| 云盘 | `FEISHU_FOLDER_MAP_JSON` | 如 `{"space_sales":"fld...","space_finance_test":"fld..."}`，每个业务空间独立目录 |
| 云盘 | `FEISHU_FILE_URL_TEMPLATE` | 租户可访问的文件链接模板，含 `{file_id}`；真实链接须联调核验 |
| 多维表 | `FEISHU_BITABLE_APP_TOKEN` 及 `FEISHU_LEDGER_TABLE_ID`、`FEISHU_DAILY_TABLE_ID`、`FEISHU_EXPECTED_TABLE_ID`、`FEISHU_SUMMARY_TABLE_ID`、`FEISHU_JOB_TABLE_ID`、`FEISHU_AUDIT_TABLE_ID` | 六张表的 token；应用须被授权读写 |
| 消息 | `FEISHU_MANAGER_CHAT_ID` | 机器人所在管理群 chat_id |
| 模型 | `MODEL_MODE`、`MODEL_API_KEY`、`MODEL_BASE_URL`、`MODEL_NAME` | `mock` 时输出模拟摘要；`real` 时使用 Responses API，请求设置 `store:false` |
| 状态 | `STATE_DB_PATH` | SQLite 回执与跨进程锁，默认 `./data/state.db`；必须放在持久磁盘并备份 |
| 调度 | `DAILY_CRON_ENABLED`、`TZ` | 启用后每分钟检查，在 Asia/Shanghai 20:00 运行当日汇总 |

`FEISHU_FINANCE_SPACE_ID` 与上述目录映射、身份空间清单必须一致。财务目录和多维表的飞书原生权限也须单独配置；应用服务的权限判断不能代替飞书 ACL。

目录文件使用飞书云盘的 `POST /drive/v1/files/upload_all`，`parent_type=explorer`、`parent_node=folder_token`；`/drive/v1/medias/upload_all` 是云文档素材接口，不能代替目录文件上传。联调时按[飞书上传文件文档](https://open.feishu.cn/document/server-docs/docs/drive-v1/upload/upload_all)核对权限与响应。

## 多维表字段契约

目前适配器按 **文本字段** 读写。真实租户建表时先按此契约创建列；日期、数字、人员和附件等富类型转换在联调确认后再改。表的主字段也需为可写文本列。字段名大小写保持一致。

- 文件台账：`archive_id`, `file_name`, `file_id`, `feishu_url`, `content_hash`, `department`, `file_type`, `confidentiality`, `uploader`, `source`, `uploaded_at`, `status`, `owner`, `version`, `previous_file_id`, `error_message`, `space_id`, `archive_key`, `updated_at`。
- 日报：`date`, `employee`, `department`, `submitted_at`, `done_today`, `metrics`, `unfinished`, `problems`, `tomorrow_plan`, `need_help`, `need_boss_decision`, `submit_status`, `confidentiality`, `test_case_id`。日报来源使用飞书返回的 `record_id`。
- 应交名单：`business_date`（日期或 `*`）、`employee`、`active`（文本 `true`/`false`）、`test_case_id`。
- 管理摘要：`summary_id`, `business_date`, `content`, `source_report_ids`, `missing_employees`, `revision`, `created_at`, `message_id`。列表字段存 JSON 文本。
- 任务记录：`run_id`, `job_type`, `business_date`, `trigger`, `status`, `started_at`, `finished_at`, `idempotent_key`, `message_id`, `error`。
- 审计：`id`, `request_id`, `operator`, `action`, `resource`, `result`, `detail`, `at`。

多维表 upsert 通过业务键查找并写入，创建时传 `client_token`；SQLite 锁约束本服务跨进程并发。部署时不可让多个实例指向各自独立的 SQLite 文件，否则锁和发送回执无法共享。

## 隔离租户的虚构数据

`samples/synthetic/` 中包含 PDF、DOCX、XLSX、TXT、版本变更 TXT 和虚构财务表 `finance-sample.xlsx`。内容均为虚构。上传时将同一文件提交两次验证去重，将 `sample.txt` 与 `sample-v2.txt` 分别以相同上传文件名提交以验证版本变化；财务样例只写财务测试目录。

六张多维表按上述文本列创建后，可在**确认当前应用与表属于独立测试租户**的环境中运行：

```bash
CLIENT_MODE=real MODEL_MODE=mock FEISHU_TEST_SEED_ALLOWED=true npm run seed:test -- 2026-10-15
```

PowerShell 可先用 `$env:CLIENT_MODE='real'` 等方式设置相同变量，再执行 `npm run seed:test -- 2026-10-15`。脚本写入应交名单 A/B/C/D、A/B 日报、A 重复提交和 D 财务敏感日报；C 缺交。`test_case_id` 是稳定键，同一天重复执行更新同一批记录。输出只含 record_id，不含凭证。执行后撤销 `FEISHU_TEST_SEED_ALLOWED`。摘要处理会排除重复提交和财务日报；模拟摘要不能标为全链路真实通过。

## 故障核对

上传请求发出后若响应丢失，`upload.state=uncertain`，自动重传暂停。用 `GET /api/v1/archives/:archiveId` 查看台账和上传回执，检查飞书目标目录后，管理员使用 `POST /api/v1/recovery/upload` 确认 `file_id`/`feishu_url`，或确认未上传。摘要发送响应不确定时 `GET /api/v1/daily-summary/:businessDate/status` 显示 `send.state=uncertain`；检查管理群消息后，用 `POST /api/v1/recovery/message` 确认已送达的 `message_id` 或确认未送达。**核对前不得自动重发。**

`STATE_DB_PATH` 丢失时，先对账飞书记录和管理群消息，再重新启用发送；不能仅凭多维表 `failed` 状态重发。

## 真实验收

资源齐备后按 [环境就绪检查表](环境就绪检查表.md) 完成权限与字段核验，再执行 T1–T10。保存可核验的文件 token/链接、台账记录 ID、摘要来源 ID、消息 ID、拒绝审计 ID 和故障恢复记录；密钥与个人敏感内容不得进入报告。最后在干净环境执行 `npm ci`、类型检查、测试、启动、MCP 工具调用和实际飞书操作。

证据状态只使用“Mock 通过”“飞书真实／模型模拟通过”“全链路真实通过”“未通过”。20:00 定时项须有测试当日实际触发记录，手动触发不能代替定时证据。

Office 在线文档导入仍在基础四类文件真实上传验收之后；当前归档保存原文件，不声称完成格式转换。
