# 部署与联调说明

当前默认 `CLIENT_MODE=mock`、`MODEL_MODE=mock`。隔离测试租户已完成四类文件、台账、日报和机器人推送的真实飞书联调；真实 DeepSeek 手动汇总与模拟模型 20:00 定时分别有独立证据。当前电脑的干净副本已用真实飞书与真实 DeepSeek 完成部署演练。

## 启动

- Node.js ≥ 22.16（使用内置 `node:sqlite`）
- `npm ci`、`npm run typecheck`、`npm test`、`npm start`
- MCP stdio：`npm run mcp`，由 MCP 宿主以进程方式启动；`MCP_API_KEY` 使用 `API_ACTORS_JSON` 中的一个密钥。日志写入 stderr，不污染协议 stdout。
- 独立测试租户可运行 `npm run verify:mcp:real:read`：脚本核对测试应用 ID，从 `API_ACTORS_JSON` 选择有公共测试空间权限的身份，经真实 MCP stdio 进程读取已知测试归档。只读输出工具名、归档 ID、文件 ID 和状态；不输出密钥。
- HTTP 默认只监听 `127.0.0.1:3000`。生产部署需由受控网关提供 TLS、访问限制与密钥注入。

## 真实模式环境变量

复制 `.env.example` 仅作字段参考，正式密钥通过运行环境或本地忽略的 `.env` 注入。`CLIENT_MODE=real` 会在启动时检查飞书必需项；只有 `MODEL_MODE=real` 才检查 `MODEL_API_KEY`。

| 类别 | 变量 | 用途 |
| --- | --- | --- |
| 入口 | `API_ACTORS_JSON` | Bearer 密钥与可信操作者、空间清单、汇总权限、财务权限映射 |
| 飞书 | `FEISHU_APP_ID`、`FEISHU_APP_SECRET` | 获取并缓存 `tenant_access_token` |
| 云盘 | `FEISHU_FOLDER_MAP_JSON` | 如 `{"space_sales":"fld...","space_finance_test":"fld..."}`，每个业务空间独立目录 |
| 云盘 | `FEISHU_FILE_URL_TEMPLATE` | 租户可访问的文件链接模板，含 `{file_id}`；真实链接须联调核验 |
| 多维表 | `FEISHU_BITABLE_APP_TOKEN` 及 `FEISHU_LEDGER_TABLE_ID`、`FEISHU_DAILY_TABLE_ID`、`FEISHU_EXPECTED_TABLE_ID`、`FEISHU_SUMMARY_TABLE_ID`、`FEISHU_JOB_TABLE_ID`、`FEISHU_AUDIT_TABLE_ID` | 六张表的 token；应用须被授权读写 |
| 消息 | `FEISHU_MANAGER_CHAT_ID` | 机器人所在管理群 chat_id |
| 模型 | `MODEL_MODE`、`MODEL_PROVIDER`、`MODEL_API_KEY`、`MODEL_BASE_URL`、`MODEL_NAME` | `mock` 时输出模拟摘要；`real` 时调用 Responses API。OpenAI 请求设置 `store:false`；DeepSeek 使用无服务端会话存储的 Responses 接口 |
| 状态 | `STATE_DB_PATH` | SQLite 回执与跨进程锁，默认 `./data/state.db`；必须放在持久磁盘并备份 |
| 调度 | `DAILY_CRON_ENABLED`、`TZ` | 启用后每分钟检查，Asia/Shanghai 20:00 起运行当日汇总；同日恢复运行时补跑，跨日不自动回填 |

`FEISHU_FINANCE_SPACE_ID` 与上述目录映射、身份空间清单必须一致。财务目录和多维表的飞书原生权限也须单独配置；应用服务的权限判断不能代替飞书 ACL。

员工 WorkBuddy 入口在同一 `API_ACTORS_JSON` 中增加独立 `kind:"employee"` 项，服务端固定 `operator`、`employee`、`department`、`spaces`、`default_space_id`、`default_confidentiality`，并设 `can_run_summary:false`。员工与管理员不得共用 key。财务员工须仅列财务测试空间，`default_confidentiality:"finance"` 且 `finance:true`。本机演示连接器从独立忽略文件读取员工凭证，WorkBuddy MCP 配置只保存该文件路径；文件通过本地 MCP 进程上传至此服务。详见 [WorkBuddy 员工入口](WorkBuddy员工入口.md)。

使用 DeepSeek API Key 时设置 `MODEL_PROVIDER=deepseek`、`MODEL_BASE_URL=https://api.deepseek.com`、`MODEL_NAME=deepseek-flash`、`MODEL_API_KEY=<本地密钥>`。客户端只允许把该密钥发送到 `https://api.deepseek.com`，不会把 `store` 参数传给 DeepSeek；摘要调用仍会把非财务虚构日报发送给模型。`MODEL_MODE=mock` 可保持定时演练使用模拟摘要，待密钥单独验证后再启动新进程切为 `real`。DeepSeek 的 Responses 参数与模型名以[官方文档](https://api-docs.deepseek.com/guides/responses_api/)为准。

密钥写入本地忽略的 `.env` 后，可仅在一次性进程中令 `MODEL_MODE=real` 并运行 `npm run verify:model:real`。该检查只发送一条虚构的非财务日报给模型，不写飞书或推送群消息，输出不含密钥与摘要正文。通过后再单独执行真实飞书＋真实模型联调。

独立测试租户完成种子写入后，可对**非当日且尚未汇总**的虚构业务日期运行真实 MCP 全链路检查。PowerShell 示例：

```powershell
$env:FEISHU_TEST_FULL_REAL_ALLOWED='true'
$testBusinessDate='YYYY-MM-DD' # 换成已种子化且未汇总的非当日日期
npm run verify:mcp:full:real -- $testBusinessDate
Remove-Item Env:FEISHU_TEST_FULL_REAL_ALLOWED
```

脚本固定核对测试应用 ID、真实飞书配置及 DeepSeek 密钥，经 MCP 调用手动汇总，实际写入摘要和任务记录并向测试管理群发送一条消息；会检查来源、缺交与财务排除。**不要用当日日期运行**，以免占用 20:00 定时验收。已有成功推送的日期默认拒绝再次运行；需要验证修订不二次推送时，显式执行 `node --import tsx scripts/verifyMcpFullReal.ts 2026-10-18 --revise`。该修订会更新摘要表，不会编辑已发送的群消息。测试后关闭 `FEISHU_TEST_FULL_REAL_ALLOWED`。

目录文件使用飞书云盘的 `POST /drive/v1/files/upload_all`，`parent_type=explorer`、`parent_node=folder_token`；`/drive/v1/medias/upload_all` 是云文档素材接口，不能代替目录文件上传。联调时按[飞书上传文件文档](https://open.feishu.cn/document/server-docs/docs/drive-v1/upload/upload_all)核对权限与响应。

## 多维表字段契约

目前适配器按 **文本字段** 读写。真实租户建表时先按此契约创建列；日期、数字、人员和附件等富类型转换在联调确认后再改。表的主字段也需为可写文本列。字段名大小写保持一致。

- 文件台账：`archive_id`, `file_name`, `file_id`, `feishu_url`, `content_hash`, `department`, `file_type`, `confidentiality`, `uploader`, `source`, `uploaded_at`, `status`, `owner`, `version`, `previous_file_id`, `error_message`, `space_id`, `archive_key`, `updated_at`。
- 日报：`date`, `employee`, `department`, `submitted_at`, `done_today`, `metrics`, `unfinished`, `problems`, `tomorrow_plan`, `need_help`, `need_boss_decision`, `submit_status`, `confidentiality`, `test_case_id`。日报来源使用飞书返回的 `record_id`。
- 应交名单：`business_date`（日期或 `*`）、`employee`、`active`（文本 `true`/`false`）、`test_case_id`。
- 管理摘要：`summary_id`, `business_date`, `content`, `source_report_ids`, `missing_employees`, `revision`, `created_at`, `message_id`。列表字段存 JSON 文本。
- 任务记录：`run_id`, `job_type`, `business_date`, `trigger`, `status`, `started_at`, `finished_at`, `idempotent_key`, `message_id`, `error`。
- 审计：`id`, `request_id`, `operator`, `action`, `resource`, `result`, `detail`, `at`。

多维表 upsert 通过业务键查找并写入，创建时传 `client_token`；SQLite 锁约束本服务跨进程并发。部署时不可让多个实例指向各自独立的 SQLite 文件，否则锁和发送回执无法共享。

## 隔离租户的虚构数据

`samples/synthetic/` 中包含 PDF、DOCX、XLSX、TXT、版本变更 TXT 和虚构财务表 `finance-sample.xlsx`。内容均为虚构。上传时将同一文件提交两次验证去重，将 `sample.txt` 与 `sample-v2.txt` 分别以相同上传文件名提交以验证版本变化；财务样例只写财务测试目录。

六张多维表按上述文本列创建后，可在**确认当前应用与表属于独立测试租户**的环境中运行：

```bash
CLIENT_MODE=real MODEL_MODE=mock FEISHU_TEST_SEED_ALLOWED=true npm run seed:test -- 2026-10-15
```

PowerShell 可先用 `$env:CLIENT_MODE='real'` 等方式设置相同变量，再执行 `npm run seed:test -- 2026-10-15`。脚本写入应交名单 A/B/C/D、A/B 日报、A 重复提交和 D 财务敏感日报；C 缺交。`test_case_id` 是稳定键，同一天重复执行更新同一批记录。输出只含 record_id，不含凭证。执行后撤销 `FEISHU_TEST_SEED_ALLOWED`。摘要处理会排除重复提交和财务日报；模拟摘要不能标为全链路真实通过。

## 故障核对

上传请求发出后若响应丢失，`upload.state=uncertain`，自动重传暂停。用 `GET /api/v1/archives/:archiveId` 查看台账和上传回执，检查飞书目标目录后，管理员使用 `POST /api/v1/recovery/upload` 确认 `file_id`/`feishu_url`，或确认未上传。摘要发送响应不确定时 `GET /api/v1/daily-summary/:businessDate/status` 显示 `send.state=uncertain`；检查管理群消息后，用 `POST /api/v1/recovery/message` 确认已送达的 `message_id` 或确认未送达。**核对前不得自动重发。**

`STATE_DB_PATH` 丢失时，先对账飞书记录和管理群消息，再重新启用发送；不能仅凭多维表 `failed` 状态重发。

独立测试租户可运行真实飞书响应丢失演练：在确认测试应用、测试群和非当日且未汇总的虚构日期后，一次性设置 `FEISHU_TEST_RECOVERY_ALLOWED=true`、`MODEL_MODE=mock`，分别执行 `npm run verify:recovery:real -- upload YYYY-MM-DD` 与 `npm run verify:recovery:real -- message YYYY-MM-DD`。脚本会在真实上传／发送返回后丢弃响应，核对 `uncertain`、禁止重复请求、管理员恢复接口和最终台账／任务；每个场景同一日期只运行一次。运行后撤销该开关。消息场景会向仅测试人员的管理群实际发送一条虚构摘要；截图核对群内仅一条消息仍需人工完成。

## 飞书管理员网页（测试租户桌面端已联调）

`ADMIN_WEB_ENABLED=false` 为默认值。部署时先提供受 HTTPS 保护的服务地址，将 `https://<服务域名>/admin` 配置为同一飞书测试应用的桌面与移动网页应用主页，并在应用“安全设置”中配置同一地址为重定向 URL；应用密钥仍只保存在服务端。设置 `ADMIN_WEB_ENABLED=true`、至少 32 字符的 `ADMIN_WEB_SESSION_SECRET`，以及 `ADMIN_WEB_ACTORS_JSON`：每项含当前应用登录返回的 `open_id`、`operator`、允许的 `spaces`、`can_run_summary:true` 和 `finance` 布尔值。只列入真正的管理员；财务空间还需 `finance:true` 且包含对应 `space_id`。不要按显示昵称授权，也不要把 API Key 填入网页。

页面使用飞书 H5 登录码，后端换取 `open_id` 并匹配白名单，签发 8 小时、HttpOnly、Secure、SameSite=Strict 的管理会话。写操作还校验同源与 CSRF。管理员可查询有权访问的文件台账、选择授权空间归档文件、手动汇总，以及查看某日任务状态、摘要正文和来源记录。测试租户桌面飞书内的真实登录、归档查询与上传、10 月 19 日日报状态和来源展示均有截图；手机端完整验收仍待补。没有应交名单且没有有效日报时，服务阻止空摘要生成与推送。服务必须持续运行；Cloudflare Quick Tunnel 地址可能失效，长期使用需固定 HTTPS 域名。当前电脑的临时演示步骤见[飞书工作台演示](飞书工作台演示.md)。

## 当前电脑干净部署复现

1. 从已推送的 `master` 克隆到新的本地目录，运行 `npm ci`、`npm run typecheck`、`npm test`。若测试在受限执行环境报 `connect EACCES 127.0.0.1`，改在允许本机回环端口的正常执行环境重跑，不能把该失败记为通过。
2. 从安全的本地配置来源提供 `.env` 或环境变量，确认应用 ID 是独立测试租户；密钥不复制进 Git。已有测试租户继续使用时，须带上原 SQLite 发送与上传回执。SQLite 采用 WAL 模式，运行中的数据库应使用 SQLite 一致性备份（本次用 `VACUUM INTO`），不要只复制 `state.db` 主文件。迁移前后确保同一时刻只有一个负责定时与发送的实例。
3. 先用其他本机端口、`ADMIN_WEB_ENABLED=true`、`DAILY_CRON_ENABLED=false` 预检 `/health`、`/admin` 和未登录 `/admin/api/me` 为 401；如验证真实模型，设置 `MODEL_MODE=real`。停止旧实例后将干净副本切到原 3001 端口，保留现有 HTTPS 隧道；重开飞书工作台，核对管理员身份、归档列表、虚构文件上传与日报状态。若临时隧道地址已变，先重新验证 HTTPS，再按测试应用安全配置流程更新主页与重定向 URL。
4. 用**非当日且未汇总**的虚构日报验收真实模型手动汇总，记录飞书摘要、来源和消息 ID；重启后只读检查任务、发送回执与归档台账。20:00 定时只在准备好当日测试数据、主机保持唤醒且仅一个实例启用 `DAILY_CRON_ENABLED=true` 时运行。当前电脑演示不等于全天候服务。
## 知识库扩展配置（2026-10-20）

此功能复用原 Express 服务、员工凭证和 WorkBuddy MCP；默认 `WIKI_ENABLED=false`。现有文件归档及日报不自动迁入 Wiki。

1. 在测试应用「权限管理」开通知识库读写、在线文档读写所需的应用身份权限；沿用原有文件上传权限。按飞书后台提示完成权限生效流程。API 权限不等于知识库成员权限，还需让应用能访问专用测试知识库及其首页。
2. 只读检查首页：`npm run check:wiki -- "https://租户.feishu.cn/wiki/首页节点"`。成功时仅打印库 ID、首页节点和名称，不打印密钥或正文。
3. 准备 Wiki 上传暂存目录（正式部署建议独立；本轮演示复用已有公共测试目录），将它加入 `FEISHU_FOLDER_MAP_JSON`（如 `wiki_staging`）。应用需可编辑该目录。不要复用财务目录；服务会上传新副本后将新副本移入 Wiki，不移动已有财务归档。
4. 设置 `FEISHU_WIKI_TARGETS_JSON` 为数组，每项含 `id`、`name`、`space_id`、`parent_node_token`、`staging_space_id`、`url_origin`，结构见 `.env.example`。首页节点必须实际属于配置的知识库，链接域名只接受 HTTPS 飞书租户域名。
5. 在获准的 hyh 员工凭证条目增加 `wiki_read_targets:["public_demo"]` 与 `wiki_write_targets:["public_demo"]`。二者独立于财务归档权限，默认均无。仅管理员核对凭证可按需加同一 `wiki_write_targets`；员工仍不能执行恢复接口。
6. 确认全部目标仅含可公开的虚构测试资料后设 `WIKI_ENABLED=true`，重启实际演示服务及 WorkBuddy MCP。不要把凭证贴入 WorkBuddy 对话；继续使用本机凭证文件。

员工 API 前缀 `/api/v1/employee/wiki`：`GET /targets`、`POST /documents`、`POST /files`、`GET /operations/:id`、`GET /nodes`、`GET /nodes/:token`。JSON 发布只接受 `target/title/content/public_test_content`，文件发布只接受 `target/public_test_content/file`。内容必须明确为公开虚构测试数据。工具不能指定实际飞书库 ID、部门或员工身份。

回执保存在已有 `STATE_DB_PATH` 的 `wiki_operations` 表，备份和迁移时包含该表。相同员工、目的地、标题和内容复用回执。`pending` 表示未确认完成；有任务 ID 时查询会读取飞书任务。`uncertain` 或无任务 ID 的长期 pending 需要人工核对，禁止自动重建或重新追加正文。部分创建的空文档或暂存文件可能保留，便于核对，不自动删除。

管理员核对流程：在飞书检查已有目标文档标题、正文完整性或原文件是否一致；必要时人工补全已有文档，不能创建第二份来绕过去重。使用具备该目标权限的管理员 API 凭证调用 `POST /api/v1/wiki/operations/:id/reconcile`，请求 `{"node_token":"已核对节点","verified_complete":true}`。服务核对库、类型、标题及已知文件/节点 ID，记录管理员审计；该接口不创建、移动或追加文档。运行中 pending 五分钟内不可恢复。接口中的确认是管理员人工核对声明，不是服务自动验证正文。

当前边界：在线文档仅写纯文本段落，最多40段，每段1000字符、总20000字符；节点列表每页50条，仅列配置首页直接子节点，需按 `next_cursor` 分页；正文读取最多20000字符，返回截断标志。附件只返回链接。权限配置、各文件类型真实移入与 hyh 飞书可见性必须另行记录，不能以 Mock 测试替代。

创建阶段无返回节点且超过五分钟时，管理员在确认远端没有结果后，可调用 POST /api/v1/wiki/operations/:id/authorize-create-retry，正文为 {"verified_absent":true}。服务完整遍历配置首页子节点，发现任何同名节点即拒绝；成功授权后，员工重发完全相同的请求只允许一次原操作重试，保留历史与审计。不能用于文件上传、已知节点或正文追加故障。管理员仍需核对是否有人移动/重命名了此前的结果，不能仅凭当前列表空自动判断不存在。

本轮运行方式为 npm start（tsx src/index.ts）。npm run build 用于生成 MCP 入口；不要直接把 dist/src/index.js 当作已打包的生产服务，当前 tsc 不复制管理员页所需 vendor 静态资源。WorkBuddy 更新代码后需在 MCP 服务管理中重连连接器，再新建对话发现工具。
